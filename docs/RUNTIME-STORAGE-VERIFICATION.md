## 写入、时钟与恢复

循环改为等待下一次可能产生实际小时结算的边界，间隔为 1–5 秒；高倍率仍保持每秒结算。批内调用原 `heartbeat`，顺序、浮点预算和每秒小时上限不变。控制、命名保存和当前状态分支会结算已发生的整秒预算；已结算部分用事务中的 credited 字段防止重复计入。加载的状态分块在保存时复用，避免同一事务读两遍。

暂停使旧 loop 与在途 AI 租约失效。AI claim/finish 也检查观察是否过期。停止服务前先通过后端事务保存暂停；启动完成前再次确认旧运行状态暂停，离线时间不结算。达到观察终点的最后一小时仍提交。

实际启动器测试保存了 3 秒部分预算；重启后运行时长与预算一致，继续等待不会推进。重复启动不创建第二套进程，不覆盖原服务的启动计时。缺失模型的隔离失败测试记录原因、释放锁，未创建服务子进程。`Start-AI-Town.cmd` 有 R 重试/Q 退出入口。

最终还实际终止了已核对身份的 Convex CLI 父进程：启动器记录失败原因，3210/3211/5173 全部关闭，确认本项目残留后端为 0；随后约 6.640 秒恢复服务，保留世界完整状态不变，Ollama 保持在线。孤儿清理同时核对本次拥有的父 PID、可执行文件路径与项目数据库路径，不按端口杀来源不明进程。见 `child-failure.json`。本文启动数字均为应用进程重新启动，未测试操作系统冷缓存或整机重启。

实际 Edge 回归通过：新局暂停、无观察不能继续、第二可见页超过 30 秒仍保活、全部观察页关闭后保存暂停、重开手动继续、手动暂停冻结、离线排队继续失效、比较页选中/取消观察。可见但无鼠标操作仍计为观察。

## 后端版本与回收配置

实际 CLI 配置及运行路径为 `precompiled-2026-10-10-72ce13c`；该 Windows 程序的 `/version` 返回 `unknown`，不能单凭此端点声称版本已核实。本轮下载官方同名 Windows 发布压缩包到 E 盘核对：发布包 SHA256 `1f7cde2e8456b3ffdc408aeee5a9f4d55e29121ecfd85f0ea9f9934ec02cbe32`，其中 EXE 与已运行 EXE 的 SHA256 均为 `19b2f9a0fbbd11b4bcb583d71fce54511a3eb9f8f19c68d5739167a0ec7c191a`。没有安装或替换后端二进制。

固定版本 SQLite 读取路径会急切加载文档日志，忽略分页大小；大库隔离启动也实测约 244 秒。来源是 [固定版本 SQLite 实现](https://github.com/get-convex/convex-backend/blob/72ce13c/crates/sqlite/src/lib.rs#L403)，不是主分支默认行为推断。

原进程没有自定义文档保留窗口，固定版本默认 14 天。现启动器明确从 `.env.windows.local` 传入并在启动记录保存：

```text
DOCUMENT_RETENTION_DELAY=21600
INDEX_RETENTION_DELAY=240
DOCUMENT_RETENTION_BATCH_INTERVAL_SECONDS=2
```

只调整技术版本回收，不改业务历史保留规则。测试：

- 新隔离库，60 秒文档窗口/10 秒索引窗口/2 秒批间隔：受控同文档 200 次更新后，技术版本实际减少 704；最终值完整，8,113 条文明业务文档摘要不变，`quick_check=ok`，未发现 retention 错误。

官方快照不携带原 Convex 内部部署/任务历史，已重新部署函数与模型环境。维护时文明全部暂停，原聊天小镇本就不活跃；业务计划、决策和原聊天数据均在逐表核对范围内。

没有直接 SQL 删除内部版本、修改回收游标或运行中替换数据库。一次官方恢复降低了当前启动负担；后续机制是边界调度、观察生命周期、固定技术窗口、可观测趋势与容量提醒，不是反复重建演示世界。

## 正式删除

`beginDeletion/deletionBatch` 是后端正式事务，只有本机维护服务持管理员凭据调用。页面按完整世界名确认，要求暂停。先导出完整官方快照，用 Python 的 ZIP64 支持核对全包 CRC、重组完整世界并比较，然后核对备份期间世界/命名保存未变化，才标记删除。

任务按每批最多 50 条推进，记录 phase、累计数量、恢复位置、快照 SHA256 和持久失败原因。重试先校验恢复文件；已完成批次不重做，完成任务重复执行不再删除。所有 pending 任务优先显示，不会被近期已完成记录挤出。保留世界被硬保护；仍有子分支的父世界拒绝删除，先处理依赖，避免孤立保留分支。

范围：该世界当前状态/分块、精确记录、已故人物档案、压缩历史块及命名存档。不会删除其他世界或共享模型缓存。逻辑删除、后台技术回收、SQLite 文件缩小在页面分别说明。恢复需先到隔离目录，导入对应完整快照及配套代码；禁止覆盖运行中的库。

隔离验证：同日压缩历史 250 条（包含 999/1000 位数边界）分页完整、无重复、数字序号倒序；分支排除父世界分叉后的同日记录；保护世界及父子依赖拦截；中断一次批次后续作；重复请求幂等。删除后的分支从实际官方快照恢复，完整状态、命名存档和历史可读；原保留世界的旧命名存档也在隔离实例经过实际解压校验并建立恢复分支。

生产仅删除本轮自己创建的验收世界，走同一正式备份/删除入口；保留世界始终未改变。

## 页面与读取性能

世界页面不再预读所有祖先；在需要人物关系时读取。已有在世人物/计划不再重复查询正文；分支元数据查询不重组整个世界。世界列表去掉仅比较图需要的样本，比较图按选中世界单独订阅；运行与存储页不订阅完整世界，不创建地图。隐藏页面停止地图及其视口 ticker，显示后恢复；未降低规则精度或掩盖真实小时更新。

实际 Edge 在同一当前后端上对旧 UI 副本/新 UI 的单轮采样：首屏订阅 `list/get/ancestors` → `list/get`；人物面板旧版又重复 `person`，新版只按需加载祖先。首屏约 3.779 → 3.070 秒、脚本约 0.601 → 0.576 秒；JS heap 本次反而约 36.8 → 41.1 MB，不能宣称内存下降。这些是单轮浏览器采样，不是稳定负载性能承诺。

中文桌面、390px 中文/英文页面、历史分页、真实删除表单均实际检查；没有页面脚本错误或整页横向溢出。长表格可在自身区域横向滚动。页面显示服务就绪后的在线时间、页面打开时间、本次启动阶段、已记录在线推进秒数、最后保存及暂停原因；以前没有记录的运行时长不从模拟年份反推。

## 仍有的限制

尚未积累跨天/跨六小时的真实生产趋势，不宣称长期大小或 RAM 已经稳定。固定后端的大范围急切加载缺陷仍存在；未来容量报警、大量世界或长时间高倍率负载可能仍需要经过单独验证的 SQLite 迁移。没有安装未发布后端补丁。

六小时技术窗口不限制精确业务历史；真实新增历史会合理增长。SQLite 能复用空闲页，文件不保证自动变小。备份保留当前是预览策略；本轮没有删除旧恢复点，没有运行 restic forget/prune。

本机管理接口由 Windows 开发启动器中的 Vite 提供，只允许 127.0.0.1 与同源操作，不是公网管理系统。生产构建导出的静态页面本身不提供本机文件维护服务。
